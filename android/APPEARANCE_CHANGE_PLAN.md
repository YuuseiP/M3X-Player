## 3. 具体设计与验收标准

### P1：曲库列表 / 方形网格

方案：在曲库排序区域加入列表、网格两个互斥按钮，清楚标示当前模式。默认沿用列表，用户切换后持久保存；关闭再打开应用仍使用该选择。

- 歌曲与分类详情的网格使用方形封面、最多两行标题、歌手信息与独立更多按钮；当前播放项保持可辨识。
- 角色、组合、歌手、专辑、文件夹分类入口也适配网格。专辑优先真实封面，其他类别沿用现有有效图像；文件夹使用文件夹图形，缺图使用现有占位图。
- 小屏起始方案为两列，按实际 Android 逻辑宽度调整；不要把 768 个物理像素直接当 CSS 宽度。卡片菜单触控区至少 48dp。
- 切换只改变呈现方式，保留当前分类、搜索、排序和歌曲集合；两个视图的滚动位置分别记录。
- 沿用现有分页 / 渐进加载，不因网格一次创建完整 4158 首歌曲节点；缩略图懒加载，行内菜单不会误触播放。
- 当前“显示封面”开关需明确关系：关闭封面时网格使用简洁占位卡，不悄悄强制开启封面。

验收：六类曲库及分类详情均可切换；搜索结果与排序保持一致；更多菜单、播放状态、长标题、空目录、无封面和重启恢复可用；收藏、队列等其他列表不被意外改变。

### P2：随歌曲封面变化的整体配色

方案：保留现有“跟随系统 / 浅色 / 深色”明暗设置，另增独立的“主题配色：固定 / 跟随歌曲封面”。为兼容旧设置，首次升级使用固定配色；启用后切歌自动更新全局颜色。

- 提取当前专辑封面的代表色，生成背景、表面、强调色、描边和文字所需的协调色阶；用户可在设置选择取色模式和恢复固定色。
- 采用莫奈风格的协调配色思路，不承诺等同于 Android 系统 Monet 算法。Android 7.1.1 不依赖新系统动态颜色接口，具体库或轻量提色实现留待实施时确认兼容性与体积。
- 优先对小尺寸封面取样；按封面标识缓存；相同封面不重复处理；快速切歌使用请求序号防止旧封面覆盖新主题。
- 缺少封面、图片读取失败或低饱和图片均有稳定回退色，避免黑屏、白字白底或刺眼大面积纯色。
- 更新覆盖曲库、播放、歌词、“我的”、设置、弹层和统计页。普通文本与背景对比度目标至少 4.5:1，控件状态不得仅靠颜色区分。
- 配色更新只触发颜色变量变化，避免重建列表与播放中断；可用短过渡，关闭动效时直接切换。

验收：不同封面切歌后更新，连续快速切歌最终颜色与当前歌曲一致；切浅深色仍可读；重启后模式恢复；暂停、播放、切歌音频行为不受影响；大量相同封面无需反复解码。

### P3：解释并改善曲库扫描入口

源码现状：曲库右上角按钮的 `data-action="scan"` 会调用 `scanLibrary()`，最终由 `/api/scan` 启动歌曲扫描，**不是二维码扫描，也不是相机入口**。现有取景框图标容易使人误解。

计划：换成更明确的曲库扫描 / 刷新图标，增加可见的“扫描”短标签；无障碍名称使用“扫描曲库”。入口附近或说明中写“扫描已授权目录，更新本地曲库”。扫描中显示进度并阻止重复启动，继续保留设置页的目录与筛选管理。

验收：点击行为仍对应原扫描流程，不新增相机权限；无授权目录时沿用目录选择引导。正式设备外观截图验收不触发扫描，扫描功能测试只在隔离测试数据上进行。

### P4：歌词页右下角更多菜单

按图示移除歌词正文上方常驻的“搜索与固化歌词”整行，以及正文下方常驻的歌词偏移条；不是删除这些能力。

- 在歌词内容区域右下角、迷你播放器上方放置 `…` 按钮，避开底部导航与当前歌词。
- 点击打开操作菜单，首层包含“搜索 / 更换歌词”“调整歌词时间”“导入歌词”“歌词保存与写入说明”；复用原有搜索、候选、标注与导入功能。
- “调整歌词时间”进入独立底部面板，保留滑块、当前数值与归零操作。已采用逐曲标注时说明偏差已经应用，避免再叠加全局偏移；延续当前限制并给出清楚提示。
- 保留逐行点击跳转、自动滚动、标题与歌手。长标题、纯文本歌词、暂无歌词、双语歌词和键盘弹出时均可操作。
- 菜单关闭后回到原歌词位置；返回键先关闭弹层，避免直接退出歌词页。关闭图标不显示意外的粗边框。

验收：主歌词页不再出现两块被圈出的常驻控件；所有原操作仍可从 `…` 到达；偏移保存规则与逐曲标注不冲突；迷你播放器和底部导航不被遮挡。

### P5：专辑感知淡变说明

源码现状：`albumTransitions` 在不同专辑之间对当前歌曲结尾、下一首开头做约 **350ms** 音量淡出 / 淡入；同一已知专辑不额外施加这段过渡。专辑比较目前依据专辑字段，未知专辑按跨专辑处理，倒放时不应用该过渡。它不是两首歌同时重叠播放的混音交叉淡化。

计划：显示名称改为“跨专辑切歌淡入淡出”，辅助说明为“跨专辑切歌时，结尾和开头短暂淡出 / 淡入；同专辑不额外淡变”。与“播放 / 暂停淡入淡出”分开说明。保持当前开关值、时长及播放逻辑，本项不扩展音频算法。

验收：首次看到名称即可理解；切换主题、打开设置、升级后原开关值不丢失；文案不把该功能说成无缝播放或音质增强。

### P6：“我的收藏 / 我的歌单”封面预览

方案：将被圈出的两条入口升级为两个紧凑预览区，分别展示标题、总数、“查看全部”和方形封面，保留完整列表能力。

- “我的收藏”：最多展示 4 首近期播放且已收藏的歌曲。现有 history 仅保留最近若干曲目，不足 4 首时按现有收藏集合顺序补齐，不声称拥有历史收藏时间。
- “我的歌单”：最多展示 4 个歌单，每个用歌单内有效歌曲封面组成方形代表图 / 拼图；点击进入该歌单。没有近期打开记录时按现有歌单顺序展示；若要按最近打开排序，从新版本开始记录，不伪造旧记录。
- 标题说明区分“近期收藏歌曲”和“歌单”，避免把歌曲封面预览误认为独立歌单。
- 当前截图中的歌单数量为 0：显示真实的空状态及“创建歌单”入口，不制造样例封面。
- 无封面、歌曲已失效、空歌单、全部未收藏均提供对应占位或空态；返回“我的”时立即反映收藏和歌单更改。
- 保留“本地歌曲”“软件设置”“听歌统计”和最近播放入口，控制卡片高度，避免封面预览挤满小屏。

验收：3 首收藏、0 个歌单的当前数据可正常显示；1 / 多个歌单、封面缺失和长标题正常；不改变歌曲 ID、收藏关系或歌单内容。

### P7：听歌统计图表与带封面的排行

源码现状：原生统计只持久保存累计秒数 `seconds` 和每首播放次数 `counts`。播放次数满足现有有效聆听阈值后记录；尚无日期、小时分布，因此**不能从目前的累计 126 分钟、48 次反推出历史时段**。

计划布局：累计摘要 → 最近 7 天听歌时长趋势 → 一天 24 小时听歌分布 → 带方形专辑封面的常听歌曲排行。

- 保留累计分钟、播放次数和现有计数口径；常听排行显示序号、封面、歌名、歌手、次数和比例条，支持进入歌曲。
- 在原生实际播放计时处增量累计按天、按小时的时长；暂停和缓冲不计时，跨小时 / 跨天按真实时间边界分配。
- 保存数据版本与统计开始日期；老版本累计数和歌曲 counts 原样保留，新图表提示“时段数据自本版本开始记录”。
- 日趋势可保留近 90 天聚合，24 小时分布按选定展示范围计算；仅存聚合数据，避免建立无限增长的逐秒记录。
- 依据设备本地时区统计；时区改变保留既有归档口径，后续数据使用当前本地时区，文案明确为本地时间。
- 无新数据时显示真实空态；只有累计值时继续展示累计值，图表不画示例历史。
- 使用轻量 SVG / CSS 图表，配文字数值与点击提示；进入统计页或数据变化时更新，避免在每次状态轮询中重建全部排行。
- 纳入既有备份 / 恢复兼容检查，缺少新增字段的旧备份可正常读取；控制新增统计对启动和轮询负载的影响。

验收：暂停不增长、播放按时长增长、跨天归档正确、重启保留、旧统计不丢、空数据不误导；排行与已有 counts 一致且有专辑图；浅深主题均可阅读。

### P8：保存歌词、写入歌曲与恢复的区别

已核对 `LyricsManager` 与歌词导入逻辑，后续界面解释采用下列真实含义：

| 操作 | 实际保存位置与行为 | 对歌曲原文件的影响 | 后续界面用语 |
| --- | --- | --- | --- |
| 采用歌词并保存逐曲标注 | 在本应用私有数据中保存所选歌词、译文与时间 / 文字标注，支持本应用离线读取 | 不改写原音频 | “保存到本应用” |
| 从地址读取并保存歌词 | 保存到本应用的歌曲对应 LRC 文件 | 不改写原音频；不是导出旁挂 LRC 到音乐目录 | “导入到本应用” |
| 固化双语歌词 | 以所选歌词和偏差生成 LRC，写入受支持歌曲格式的歌词标签，并回读校验 | 会修改歌曲文件，操作暂停播放；先保存完整恢复副本 | “写入歌曲文件” |
| 固化恢复 | 使用对应恢复副本恢复固化前的完整文件，保留现有一致性检查 | 恢复的是整首歌曲文件，并非仅撤销当前界面文字 | “恢复写入前的歌曲文件” |

计划：在搜索面板把两种主要操作分开，短说明直接放在按钮附近；将“固化恢复记录”改为“歌词写入与恢复记录”，写入前保留覆盖原歌词、备份空间、支持格式、暂停播放及卸载会删除应用内备份的提示。原有中断写入和外部修改保护继续保留。

验收：用户能在执行前分清“仅本应用使用”和“改写歌曲文件”；仅保存不触发音频文件写入；写入与恢复只用可丢弃歌曲副本做功能测试，禁止在用户原曲上为截图构造写入成功状态。

## 5. 后续测试计划

用户目前没有连接 M3X，后续恢复实施时按用户要求先用虚拟机测试。本次不启动虚拟机、不安装 APK、不运行以下测试。

1. **代码与构建**：检查改动范围；运行 `android/package.json` 中的 assets 构建；执行对应 JS / JVM 检查与 release 构建，确认 Android 7.1.1 兼容构建要求。
2. **有意义的逻辑验证**：统计跨日 / 暂停 / 旧数据迁移；动态配色快速切歌与失效请求；列表 / 网格歌曲集合和设置恢复；歌词偏差不重复应用。
3. **虚拟机交互验证**：先检测可用模拟器及 Android / WebView 版本，再在隔离曲库上验证 P1–P8。目标逻辑窗口、字体缩放和触控区参照 M3X，包含浅色 / 深色、空态 / 有数据、无封面、长曲名与 4000+ 项曲库。
